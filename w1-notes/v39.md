**Independent review (orchestrator) of `24d048b..a0fc244` (#32 part 1: the forwarder and its egress allowlist): REQUEST_CHANGES. No egress bypass was found; one medium and a set of robustness and test fixes are needed**

Two reviewers looked at this PR: one at the address and allowlist checks, one at the proxy as a network service. Skeptics checked each serious finding. They lowered three to low, and refuted a fifth, about unbounded refusal logging, to a nit.

**What holds:**
- **The address checks are correct.**
  - A 189-case table covers every IANA special-purpose IPv4 and IPv6 range, at each edge and just outside it. It also covers mapped, compatible, SIIT, NAT64, 6to4 and Teredo forms, zone IDs, brackets, and decimal, octal, hex and short IPv4 forms. Nothing unexpected.
  - A 197,277-form IPv6 fuzz, checked against the URL parser's canonical form, found 0 mismatches.
- **The allowlist fails closed.**
  - All 56 entries that should throw do throw.
  - 74 `checkTarget` cases (wildcard against apex, suffix tricks, ports, trailing dots, punycode, mixed public and private answers, a lookup that throws or returns nothing) found nothing unexpected.
  - An empty list allows nothing, and an unlisted name or an IP literal never reaches DNS.
- **Judgment call C holds:** every DNS answer is checked, and the connection goes to the checked address on both paths. 44 raw CONNECT and GET probes, including pipelined keep-alive requests, never connected to a refused target.
- **Parsing and limits hold:**
  - A conflicting `Content-Length` and `Transfer-Encoding` get a 400, and a refused request's body isn't parsed as a request.
  - Control bytes in a target or header get a 400, so nothing reaches the log or the headers.
  - A 70 KB header gets a 431.
  - 1,500 concurrent CONNECTs plus slowloris sockets don't crash it, and neither does EMFILE under `ulimit -n 200`.
- **Judgment call F holds:** it imports only `node:` modules, and a bad config exits 1 in the cases tested (but see below).
- **Tests:** 723/723 at `a0fc244`, and CI green.

**Please fix:**
1. **A CONNECT tunnel closed by the idle timeout never closes the PR's socket** (`lib/forwarder.mjs:250`). `upstream.destroy()` on idle emits no `error` and no `end`, so the client side stays open and paused, even after the PR closes its own end. With a short `IDLE_MS`, held connections grew with every round. Add `upstream.on('close', () => socket.destroy())`, arm an idle timeout on the client socket too, and test that `getConnections` returns to 0.

**Low** (all small, in this file or its test):
- **A listed upstream answering with status 000–099 crashes the whole forwarder:**
  - `res.writeHead` throws, nothing catches it, and the inbound forward dies with it.
  - The PR can't trigger this alone: it needs a listed plain-HTTP host that sends such a status. It also fails closed.
  - The fix is one line: check the status is 100–999, otherwise answer 502 `failed`. Add a `HTTP/1.1 000` test.
- **Mutants that would open egress survive the tests:**
  - an exact host matched as a suffix, which would admit `evilapi.example.com`;
  - only the last DNS answer checked;
  - CGNAT narrowed to `/16`, which would pass `100.100.100.100`;
  - a wildcard ignoring the port;
  - production `connect` and `lookup` swapped.

  The review's `egress/mut/test/extra.test.mjs` kills all of them. Add one socket test that leaves `connect` at its default and spies on `net.connect`.
- **15 of 22 service mutants survive.** Missing tests:
  - Host header override;
  - hop-by-hop headers in both directions;
  - connect and idle timers;
  - CONNECT head bytes;
  - 502 on both paths;
  - the forward with the app down;
  - tunnel close from either side.
- **The test file can still hang:**
  - A wrongly allowed CONNECT leaves the 200 tunnel open, and `close()` never resolves while a tunnel is open.
  - A timed-out socket test never runs its `finally`. Orphaned runners and a forwarder child stayed listening for minutes.

  Destroy tracked sockets in `close()`, register cleanup with `t.after()` (which does run on a timeout), or use `--test-force-exit`. Then the commit and body claims hold.
- **The plain-HTTP connect timer** starts only after connect, so a connect that never completes isn't bounded. It also cuts any response idle for 10 s. Use an explicit connect timer, plus a separate, longer idle timer.
- **Error paths:**
  - An upstream that ends partway through the body leaves the PR's response hanging; destroy `res` on an incomplete close.
  - After the 200, a CONNECT failure writes an HTTP 502 into the tunnel. A CONNECT 502 is also labelled `refused`, where the HTTP path says `failed`. After the 200, just destroy the socket, and use `failed` for 502 on both paths: PR 2's probe will key off this header.
- **Headers named in `Connection`** aren't dropped as hop-by-hop (RFC 9110 §7.6.1).
- **The inbound forward drops the response when a client half-closes;** use `allowHalfOpen: true` on both sides.
- **Config validation:**
  - A config with neither `forward` nor `proxy` (`{}`, `[]`, `"x"`) prints "ready" and exits 0.
  - The forward listens before the proxy config is validated.

  Validate the whole config first.
- **The HTTPS guarantee is per address, not per host:** inside an uninspected tunnel, SNI and Host can name any site on a listed name's IPs. Say so in the header comment and in PR 2's README, and warn against listing names on shared CDNs.
- **`parseAllowlist` accepts private names written as host names,** such as `0x7f.0x0.0x0.0x1`, `foo.localhost`, `host.docker.internal` and `metadata.google.internal`. They are refused at run time, so this isn't a bypass, but judgment call A says they throw. Canonicalize entries and CONNECT hosts as the HTTP path already does, or narrow the claim.
- **Untested refused ranges:** Teredo, `192.0.0.0/24`, `192.88.99.0/24`, the TEST-NETs, `0.0.0.0/8` beyond `0.0.0.0`, and the `2000::/3` bound. Add far-edge cases, as in `extra.test.mjs`.

**Nits:**
- **IPv6 entries are compared as strings:** an unbracketed IPv6 entry with a port silently becomes another address, and zone IDs are accepted. Require brackets, and canonicalize.
- **Judgment call B wording:** it should say mapped addresses are judged as IPv4.
- **`parseAllowlist`:** it has a dead one-label-wildcard clause, and accepts multi-label public suffixes such as `*.co.uk` and `*.github.io`.
- **`close()`** never resolves while a forward connection is open.
- **The refusal log line:** it's ambiguous for IPv6 and malformed ports, and has no length bound; bracket the host, or use `JSON.stringify` and truncate.
