**Please fix:**
1. **High: the new `maxCollections` cut is by name** (`lib/data-diff.mjs:287`).
   - The PR's migration adds 1,000 one-row collections, `aaa0000`…`aaa0999`. `users` is then left out of every PR snapshot, and nothing marks it.
   - A reviewer action that wipes all 50 users then shows in the session span as `flags = []` and divergence `users: same`, whether the session is isolated or not. The control without the padding gives red delete, emptied and mass-change.
   - The only traces are a false boot-span `users dropped` (the table still exists) and an unnamed "1 collections past the first 1000 were left out".
   - Fix:
     - never drop a collection silently: past the cap, keep a count-only stub marked truncated, so it raises `unverified`;
     - or cut by row count, not by name;
     - in `flagChanges`, raise a red `unverified` for any collection in the base diff that the PR diff lacks;
     - in `divergence`, answer `unknown`, not `same`, when one side lacks the collection;
     - add a test with 1,000 padding collections in S1 and Sn.
2. **A regression: a `Set` or `Map` in a secret-named, classify-secret or PII field is now shown in clear** (`:249`). `isSet` still calls a `Set` unset, so `cell()` skips masking, and the new `toJson` line serializes the entries. Examples:
   - a `recovery_codes` Set gives `["RC-1111","RC-2222"]`;
   - a classify-secret `vault` gives `["vault-secret"]`;
   - a PII `emails` field gives `["jane@example.org"]`.

   At `72ad7c3` each was `{}`. Decide `isSet` by `.size` for `Set` and `Map`, serialize entries the same way for the fingerprint, and test all three classes.
3. **The new text scan is super-linear** (`:178`). `secretKeyIn`'s regex retries up to 64 lengths at every position.
   - A 20 MB text cell now takes 11 s, against 92 ms before. 200 NDJSON cells of 250 KB take 43 s, against 0.2 s before.
   - It runs synchronously in #36's `take()`, after the inspector's timeout has stopped counting.
   - Fix:
     - anchor the scan at a word start, for example `/(?<![\w.-])["']?([\w.-]+)["']?\s*[:=]/g`, which took 141 ms on 20 MB;
     - skip text with no `:` or `=`;
     - scan at most `HELD_JSON_MAX` characters;
     - bound the NDJSON work;
     - add a timing test.
4. **Text masking still misses keys written with escaped quotes or brackets** (`:178`). These are still raw:
   - double-encoded JSON (round 1's own `dbl` case);
   - `body="{\"password\":\"…\"}"` inside a log line;
   - `user[password]=…` form parameters.

   The CHANGELOG claims more than the code does. Allow `\\?["'\[]?…\\?["'\]]?` around the key, re-parse a JSON string literal whose content starts with `[` or `{`, and test all three.
5. **The cache can still hold about 440 MB** (`:172`). It caps 1,000 collections × 10,000 fields each, which is 10 million entries: fresh names spread over 1,000 collections plateau at 440 MB retained, with 1.19 GB of process memory. Cap the total number of entries (say 50,000), or cache only the per-collection rule lookups, and test the total.
