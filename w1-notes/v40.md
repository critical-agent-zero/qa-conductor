**Please fix:**
1. **With `internal` configured, a setup failure silently restores full egress** (`lib/adapters/provisioner-docker.mjs:300`, `:558`).
   - Example, on Linux Docker Engine: pulling `node:22-alpine` fails, which a Docker Hub rate limit is enough to cause. The Provisioner then:
     - undoes the topology;
     - runs the PR app on an ordinary network, published, with no proxy env;
     - keeps the verdict `isolated` with no reason, because the failure reason is added only when the verdict isn't `isolated`;
     - logs nothing.
   - So the operator's `internal.egress` allowlist is dropped without a word, `QA_REQUIRE_ISOLATION=1` lets the boot run, and the README says "It fails closed".
   - The exposure is the same as without `internal`, so this opens no new route; hence medium. But an operator who asked for an egress allowlist must be told when it isn't in force.
   - Conservative default, to flag as a judgment call in the body:
     - when `internal` is set and the topology falls back, cap the check's result at `unknown`, with the reason "egress isn't restricted: the PR pane's internal network couldn't be set up (…)". Strict mode then refuses, and the chip shows it;
     - always log the fallback;
     - reword the "fails closed" heading;
     - add a Linux-runtime test (no Docker Desktop reason) asserting the fallback isn't `isolated`.
2. **The README claims nothing but proxied HTTP(S) leaves the internal network** (`README.md:555`, `:577`).
   - On Docker Engine before 23.0.11, 25.0.0–25.0.4 and 26.0.0-rc1–rc3, dockerd forwards DNS from internal networks through the host's resolver when that resolver is on loopback (systemd-resolved or dnsmasq). This is CVE-2024-29018, GHSA-mq39-4gv4-mvpx.
   - PR code can then exfiltrate data in DNS queries to its own nameserver, which breaks decision E. Docker Desktop isn't affected, and Podman's aardvark-dns answers NXDOMAIN for external names.
   - Fix:
     - give the PR pane's containers a `--dns` pointing at a non-loopback, unroutable address (the advisory's workaround, which covers every version);
     - state the limit in the README;
     - add `docker run --rm --network qa-session-pr busybox nslookup example.com` (must fail) to the check by hand.
