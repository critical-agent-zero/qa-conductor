# qa-conductor 0.2.0: local process panes, git-worktree builds, self-QA

**Date:** 2026-09-26 · **Status:** approved design, revised after an adversarial spec review (four lenses, 32 confirmed findings folded in)

## Why

0.1.0 ships one built-in Provisioner, which runs panes as Docker containers, and assumes builds happen in CI. Its second consumer, agent-identity, runs panes as **local processes** (a Node dev server per pane plus DynamoDB Local) and builds a PR by **checking it out and installing dependencies**. qa-conductor itself can use the same two pieces to QA its own UI in a demo mode.

This release:
- adds those two pieces as built-in adapters;
- fixes the core gaps the second consumer exposed;
- **makes the harness safe to run on a developer laptop**, where until now it has run behind homefree's droplet and tailnet;
- adds a demo mode.

## Constraints (all units)

- **Plain ESM `.mjs`, Node ≥ 22, zero runtime dependencies**, tested with `node:test` (`npm test` runs `node --test test/*.test.mjs`).
- **Every effect is injected:** process spawning, `kill`, `execFile`, `ps`, filesystem, `fetch`, free-port lookup, sleep, the clock and exit hooks. Each factory defaults its effects to the real Node APIs. Tests run with no real Git, processes or network, apart from loopback servers the test itself starts.
- **Match the house style:** a file-top comment block explaining the module's job, sparse `//` comments explaining *why*, and small named functions.
- **Units are developed in parallel from `main`**, so a unit must not depend on another unit's unmerged code. Where one unit consumes another's change (for example U2 reading `err.stdout` from U1's `exec.mjs`), it handles both the old and the new shape. Each unit adds only its own entries to `package.json` (`exports`/`scripts`) and the README; conflicts are resolved at merge time.
- **Security is part of every unit's acceptance.** The trust gate is the only real boundary between a PR's code and the reviewer's machine. Env scrubbing and loopback binding are defence in depth. The docs must say exactly that.

## U1: core

1. **Config.**
   - `QA_OPERATOR_EMAIL` is optional; `operatorEmail` is `null` when unset.
   - `QA_PUBLIC_HOST` is required only when `QA_BASE_ORIGIN` and `QA_PR_ORIGIN` aren't both set; otherwise `publicHost` defaults to `null`.
   - `loadConfig(path, { defaults, required = [] })` lets a platform re-require keys, for example homefree re-requiring `QA_OPERATOR_EMAIL`. `GITHUB_QA_TOKEN` and `QA_REPO` stay always required.
2. **Listen host (a behaviour change).** `cfg.host` comes from `QA_BIND_HOST` and defaults to **`127.0.0.1`**. `startConductor` passes it to all three `listen` calls, and the log lines print `host:port`.
   - README: anything other than loopback exposes an unauthenticated API that returns pane login URLs and posts verdicts with `GITHUB_QA_TOKEN`, and a pane proxy *is* an authenticated pane session because the proxy holds the cookie jar. Widen it only behind a firewall or an authenticating front door.
   - homefree migration note: its RC app reaches the harness over the Docker bridge, so it will need `QA_BIND_HOST=0.0.0.0` when it moves to the package.
3. **Browser-request hardening (a behaviour change).**
   - **(a) Host allowlist.** All three servers check the `Host` header before routing. The hostname (port ignored, `[]` stripped) must be `127.0.0.1`, `localhost`, `::1`, `cfg.publicHost`, the hostname of either `cfg.paneOrigins` entry, or an entry in `cfg.allowedHosts` (`QA_ALLOWED_HOSTS`, comma-separated). Anything else gets `421`. `createPaneProxy` gains an `allowedHosts` option. This defeats DNS rebinding.
   - **(b) Origin check.** Every harness `/api/*` request other than GET/HEAD (after the `/qa` prefix is stripped) must pass this check. If `sec-fetch-site` is present, it must be `same-origin` or `none`. Otherwise, if `origin` is present, `new URL(origin).host` must equal `req.headers.host`. Anything else gets `403`.
   - **(c) Content type.** `POST /api/session`, `/api/verdict` and `/api/teardown` require the media type `application/json` (compared case-insensitively, before any `;`), or get `415`. `public/harness.js` sends `content-type: application/json` with body `'{}'` on its teardown calls. The `api()` helper in `test/server.test.mjs` always sends the header on POST.
4. **Generic build progress.**
   - `onBuild` payloads are `{ runUrl?, runStatus?, message? }`. The server keeps `buildRun = { url, status, message }`, broadcasts `{ kind:'build', runUrl, runStatus, message }`, and `/api/state` includes it.
   - The UI renders `message` with **`textContent`**, never `innerHTML`, and appends a run link built with `createElement('a')` only when `runUrl` matches `/^https:\/\//i`.
   - `esc` also escapes `"` and `'`.
5. **Generic step labels.** One `LABELS` map in `harness.js` (`ensuring-image` → **Building**, `cloning` → **Preparing data**, `migrating` → **Migrating**, `starting` → **Starting**) is used in `markStep`, `showBootError` (the error line and its announcement) and to set the `<li>` text in `index.html`. 'Image cached' becomes 'Already built'. The step ids are unchanged.
6. **Trust data from GitHub.**
   - `createGithub` gains `prInfo(num)` → `{ number, headSha, author, authorAssociation, isDraft, headRepo, headOwner }`, from `GET /repos/{repo}/pulls/{num}`. `headRepo` is `head.repo?.full_name ?? null`, and `headOwner` is `head.repo?.owner?.login ?? null`.
   - It also gains `authorPermission(login)` → the top-level `permission` (`admin|write|read|none`) from `GET /repos/{repo}/collaborators/{login}/permission`. It throws on a non-2xx response.
   - `listOpenPrs()` items add `authorAssociation`, `headRepo` and `headOwner`.
7. **A `blocked` readiness status.**
   - `describePrs` may return `status: 'blocked'` with a plain-text `reason`. `/api/prs` passes `reason` through.
   - `/api/build-status` uses `github.prInfo(pr)` when available, passing `{ number, headSha, author, authorAssociation, headRepo, headOwner }` to `describePrs`, and falls back to `prHead`. It adds `reason` to its response **only** when the status is `blocked` (with `exists: false`), so the existing shape is otherwise unchanged.
   - The picker shows a grey badge with the text `can't boot: <reason>`, set via `textContent`. Opening the PR is still allowed, because `ensureBuilt` is the real gate.
8. **Mirroring contract (the `#qa=` fragment).** A pure helper `withQaFragment(url, harnessOrigin)` in `harness.js` appends `qa=<encoded harness origin>` to a landing URL's fragment: `#qa=…` when there's no fragment, `&qa=…` after an existing one. If the fragment already has a `qa` param, the URL is returned unchanged.
   - `renderSession` applies it to both iframe `src` values, with `location.origin`.
   - The helper is exported through the same CommonJS guard `bridge.js` uses, and the IIFE is guarded with `typeof window === 'undefined'`, so `node --test` can load it.
   - README (AuthBootstrap): the harness appends `qa=` to each landing URL's fragment. Adapter fragments must be `&`-separated `key=value` pairs, and the app must keep the hash through redirects until the first HTML load.
9. **Display label.**
   - `resolveBaseImages` and `resolvePrImages` may return a `label` string. `bootSession` then uses `baseTag`/`prTag` = `label ?? services[primary]`.
   - README: the label appears in the harness header and in the **public** verdict comment, so consumers whose service refs are local paths or objects must set it. It must not contain `:`.
10. **Cancellation reaches the Provisioner.**
    - `bootSession` runs `checkpoint()` at the top of every per-role iteration (before `provisionDatabase`), before each `launchServices`, and before the `waitHealthy` loop.
    - It passes `signal` to every Provisioner call: `provisionDatabase`, `reserveServices`, `runMigrate`, `launchServices` and `waitHealthy`. Provisioners may ignore it; the Docker one does.
11. **Failure log tails are read before teardown.**

    - `lib/exec.mjs` `makeExecFileFn` rejects with an Error that also carries `stdout`, `stderr` and `code`, with its message unchanged.
12. **Shutdown.** `startConductor` also returns `async shutdown()`. It clears the reaper, awaits `doTeardown()` (which aborts the in-flight boot and tears down both panes), ends the SSE responses, calls `closeAllConnections()` on all three servers, and awaits their `close`. `stop()` is unchanged.

It also documents `prInfo`, `authorPermission`, the progress `message`, `blocked`, `label`, `signal`, `logTail`, `shutdown()`, `QA_BIND_HOST`, `QA_ALLOWED_HOSTS` and the `#qa=` contract. ## U2: `lib/adapters/build-worktree.mjs` (git-worktree BuildConvention)

```js
createWorktreeBuild({
  repo,                         // 'owner/name'
  cloneUrl,                     // default `https://github.com/${repo}.git`; must NOT contain credentials (throw at construction)
  cacheDir,                     // e.g. ~/.cache/qa-conductor/<owner>-<name>
  github,                       // must provide prInfo(num) and authorPermission(login)
  servicesFor,                  // (worktreeDir, { role: 'base'|'pr', sha }) => ({ [service]: ref })
  install = null,               // null = no install; else { cmd, args, env? } — recommend --ignore-scripts (pnpm: also --ignore-pnpmfile)
  baseRef = 'main',
  trust = { logins: [], associations: ['OWNER', 'MEMBER', 'COLLABORATOR'], requirePush: true },
  keep = 6,                     // worktrees retained after pruning
  migrationStrategy = 'on-boot',
  execFileFn, fsx, baseEnv = process.env, nowFn,   // injected (execFileFn defaults to makeExecFileFn())
})
// => { migrationStrategy, subscribeBuild, ensureBuilt, resolvePrImages, resolveBaseImages, describePrs }
```

- **Trust: `trustDecision(info, { repo, trust, permission })` → `{ ok } | { ok:false, reason }`.** This pure, exported helper is used by both `ensureBuilt` and `describePrs`. A PR is trusted only if **all** of these hold:
  - **(a)** `info.author` is in `trust.logins` (case-insensitive), **or** `info.authorAssociation` is in `trust.associations` **and**, when `requirePush` is set, the author's `permission` is `admin` or `write`.
  - **(b)** `info.headRepo` is non-null. The reason otherwise is 'head repository was deleted'.
  - **(c)** `headRepo` equals `repo` (case-insensitive), or `headOwner` equals `author` (case-insensitive). The reason otherwise is `head branch is in @<headOwner>'s fork (<headRepo>), not the author's`.
  - Any error fails closed.
  - `author_association` alone is not an access check: `COLLABORATOR` includes read-only outside collaborators, and `MEMBER` includes org members with no push access.
- **Validation:**
  - Every SHA (from GitHub or git) is trimmed and must match `/^[0-9a-f]{40}([0-9a-f]{24})?$/`.
  - PR numbers must satisfy `Number.isSafeInteger(n) && n > 0`.
  - Any `rm -rf` target must resolve inside `${cacheDir}/worktrees/`.
- **Layout:**
  - A bare repository at `${cacheDir}/repo.git`, created with `git init --bare` on first use.
  - Worktrees at `${cacheDir}/worktrees/<sha>`, named by the full SHA.
  - **Markers outside the checkouts**, at `${cacheDir}/built/<sha>.json` with body `{ sha, builtAt, installFingerprint }`. The fingerprint is a SHA-256 of `install` cmd, args and env keys, and a mismatch counts as not built.
- **`ensureBuilt(pr, { signal })`:**
  1. `info = await github.prInfo(pr)`, then `permission` via `authorPermission` when needed, then `trustDecision`. On failure, throw `Error('PR #N by @author is not from a trusted source: <reason>')` **before any git call**. This step runs outside the lock.
  2. **One build at a time.** Steps 3 to 6 run under one in-process async lock per instance. A caller that arrives while another holds it waits, ignores that call's outcome, then runs the steps itself, re-checking the markers. There is no shared promise, because an aborted caller's `AbortError` must never reach a live boot. After acquiring the lock, check `signal.aborted` and throw an `AbortError`. Every `execFileFn` call gets `{ signal }`.
  3. **Fetch** (with `GIT_TERMINAL_PROMPT=0`): `git --git-dir <bare> fetch --no-tags <cloneUrl> +refs/heads/<baseRef>:refs/qa/base +refs/pull/<pr>/head:refs/qa/pr-<pr>-incoming`, then `rev-parse` both refs.
     - If the incoming SHA isn't `info.headSha`, call `prInfo` once more. Require that its `headSha` equals the fetched SHA and that `trustDecision` passes again; otherwise throw `Error('PR #N head moved during fetch; retry')`.
     - Only then run `update-ref refs/qa/pr-<pr> <sha>`.
     - Record the resolved SHAs for `resolve*` only if the signal still isn't aborted.
     - **Only the exact SHA that passed the trust check is ever checked out or installed.**
  4. **Worktree** for each of base and PR, unless a valid marker exists:
     1. `git --git-dir <bare> worktree prune`, to drop registrations whose directory was deleted.
     2. If `<dir>` exists, clean it, tolerating failures: `worktree remove -f -f <dir>`, then `rm -rf <dir>`, then `worktree prune`.
     3. `git --git-dir <bare> worktree add -f -f --detach <dir> <sha>`.
  5. **Install** in `<dir>`: `execFileFn(install.cmd, install.args, { cwd: dir, signal, env: { PATH, HOME, ...install.env } })`, taking `PATH` and `HOME` from `baseEnv`, so nothing else is inherited.
     - On failure, throw `Error('install failed for <base|#N> (<sha7>): <cmd> exited <code>')` with `err.logTail` set to the last 40 lines, at most 8 KB, of `err.stdout + err.stderr`, falling back to `err.message`.
     - Write the marker last.
  6. **Prune** (best-effort, and never fails `ensureBuilt`): keep the newest `keep` markers by `builtAt`, and never the two SHAs just built. For each of the rest: `worktree remove -f -f`, falling back to `rm -rf`, deleting the marker, then `worktree prune`. Report failures as progress messages.
  7. **Progress** via `subscribeBuild(cb)` with `{ message }`: `fetching <repo>…`, `installing dependencies for base (<sha7>)…`, `#N (<sha7>) already built`, and so on. Callback errors are swallowed.
- **`resolvePrImages(pr)`** returns `{ services: servicesFor(dir, { role:'pr', sha }), migrate: null, label: '#<pr>@<sha7>' }`. **`resolveBaseImages()`** returns `{ …, label: '<baseRef>@<sha7>' }`. Labels never contain a filesystem path.
- **`describePrs(prs)`**, where the items are `listOpenPrs()` items:
  - `blocked`, with the reason, when `trustDecision` fails. `authorPermission` is memoized per login with a 5-minute TTL on `nowFn`, and an item missing `authorAssociation` isn't judged on trust.
  - Otherwise `building` if its SHA holds the lock, `built` if a valid marker exists, and `none` otherwise.
  - `runUrl` is always `null`.
- **`package.json` `exports`:** add `"./adapters/build-worktree"`. Test it through a package self-reference.

**Tests** use a recording `execFileFn` and an in-memory `fsx`. They cover:
- each trust branch, all of which throw before any git call: a read-only collaborator, a login allowlisted in `trust.logins`, a foreign-fork head, a null head repo, a same repo in different case, the author's own fork, a permission error failing closed;
- a moved head, re-gated or failing with 'retry', where `refs/qa/pr-N` is never set to an ungated SHA;
- the fetch refspecs, and `signal` on every exec;
- worktree prune/add, and a skip when the marker is valid;
- a partially built directory, cleaned with `remove -f -f` and `rm -rf`;
- a marker whose fingerprint doesn't match;
- a second caller waiting for and then re-running after an aborted first build;
- abort after taking the lock;
- prune keeping `keep`, never removing current SHAs, and tolerating failures;
- the install failure's `logTail` from stdout;
- the installer env being exactly `PATH`, `HOME` and `install.env`;
- SHA and PR validation;
- every `describePrs` status;
- `resolve*` returning labels with no paths;
- credentials in `cloneUrl` being rejected;
- progress messages, with callback errors swallowed.

## U3: `lib/adapters/provisioner-process.mjs` (process-based Provisioner)

```js
createProcessProvisioner({
  command,                      // ({ name, ref, port, env, paneRef }) => { cmd, args, cwd, env? }
  database = null,              // optional: { command({ paneRef, port }) => { cmd, args, cwd?, env? },
                                //             ready({ port, signal }) => Promise<void>,
                                //             handle({ paneRef, port }) => { dsn, db } }
  healthPath = '/',             // string, or (serviceName) => string
  healthy = (status) => status < 500,   // predicate, e.g. C2 requires 200 on /ui/
  healthTimeoutMs = 60000,
  stateDir,                     // pidfile directory (created 0700, must not be a symlink, must be owned by the current uid)
  host = '127.0.0.1',           // the address used in reserved urls, health checks and free-port lookup
  graceMs = 5000,               // TERM → KILL
  logLines = 200,
  spawnFn, killFn, freePortFn, fetchFn, fsx, psFn, pgroupFn, sleepFn, nowFn, onExitFn, baseEnv = process.env,  // injected
})
// => { provisionDatabase, reserveServices, launchServices, waitHealthy, logs, sweep, teardown }
```

- **Launch contract, documented in the README.** `command` and `database.command` must start the server binary **directly**, never through a package manager (`pnpm dev`, `pnpm exec`, `npm run`, `npx`). The child has no TTY and only `PATH` plus the declared env, and the package manager on that PATH may not be the one that ran `install`: pnpm 10 and later verify dependencies before run/exec and, with no TTY, fail or reinstall. So use, for example, `{ cmd: join(dir,'node_modules/.bin/tsx'), args: ['packages/api/src/dev.ts'], cwd: dir }` or `{ cmd: process.execPath, args: ['demo/server.mjs'], cwd: dir }`.
- **Child envs, exactly:**
  - a service gets `{ PATH: baseEnv.PATH, ...env[name], ...spec.env }`;
  - the database gets `{ PATH: baseEnv.PATH, ...spec.env }`.
  - Nothing else is inherited: no credentials, and no `HOME` unless declared.
- **`provisionDatabase({ paneRef, signal })`:** with no `database`, return `{ dsn: null, db: null }`. Otherwise:
  - pick a free port, check `signal?.aborted` and throw an `AbortError` if so, then spawn;
  - `await database.ready({ port, signal: AbortSignal.any([signal, exitSignal]) })`, where `exitSignal` aborts if the database process exits; on an early exit, reject with the log tail;
  - return `database.handle(...)`.
- **`reserveServices({ paneRef, services })`:** a free port per service on `host`, drawn from an in-process allocated-port set so ports never collide, as `{ [name]: { url: 'http://<host>:<port>', port } }`. Nothing starts yet.
- **`launchServices({ paneRef, services, env, reserved, signal })`:** for each service, check `signal?.aborted` immediately before `spawnFn`, then spawn `command({ name, ref: services[name], port: reserved[name].port, env: env[name] ?? {}, paneRef })`.
- **Spawning rules:**
  - `spawnFn(cmd, args, { cwd, env, detached: true, stdio: ['ignore','pipe','pipe'] })`.
  - In the **same synchronous tick**, record the child in the in-memory per-role table and attach the `error` and `close` listeners, plus `error` listeners on stdout and stderr. `error` or `close` is the terminal state; `exit` alone is not relied on.
  - If `child.pid` isn't a positive integer, the spawn failed: don't record a pid, wait for the `error` event, and reject with `Error('<name>: failed to start <cmd> in <cwd>: <err.message>')`. Processes already spawned stay recorded, so the core's failure teardown kills them.
  - After spawning, call `psFn(pid)` → `{ startedAt }`. The default is `ps -o lstart= -p <pid>` with `LC_ALL=C`.
  - Persist `{ pid, startedAt, paneRole, kind, name, cmd, args }` to `${stateDir}/pids.json`. Writes are serialized through one promise chain as tmp-file-then-rename, with mode `0600`.
  - Capture stdout and stderr lines into a per-role ring buffer (`logLines`), prefixed `[name]`.
  - On the first spawn, register an exit hook through `onExitFn`, defaulting to `process.on('exit')`. It **synchronously** sends SIGKILL to every live group. It runs only on `process.exit` or natural exit, not on signals: CLIs call the conductor's `shutdown()` on signals.
- **`waitHealthy({ services, signal })`:**
  - For each service with a port, `deadline = nowFn() + healthTimeoutMs`.
  - Each attempt creates an `AbortController`, then races `fetchFn(url, { signal })` against `sleepFn(min(2000, remaining))` and against the process having exited, and aborts the controller in a `finally`.
  - `healthy(status)` means done. An early exit fails immediately with the log tail. Past the deadline, throw `<name> on port <port> not healthy after <ms>ms` with the tail. Otherwise sleep 250 ms and retry.
  - An aborted `signal` stops the wait with an `AbortError`.
- **`logs({ paneRef, stage, lines = 40 })`:** the last `lines` of the role's buffer. **Teardown keeps the buffer**; it's reset only when the next `provisionDatabase` or `launchServices` for that role starts.
- **`teardown({ paneRef })`** acts on process **groups**, never on leaders, because a wrapper may exit at once while the server survives:
  1. Services first, then the database: `killFn(-pid,'SIGTERM')`, tolerating ESRCH.
  2. Probe with `killFn(-pid, 0)` every 100 ms until ESRCH or EPERM (gone) or `graceMs` elapses; then `SIGKILL` and probe again for up to 2 s.
  3. Remove a pidfile entry only once its group is gone. A group that survives SIGKILL keeps its entry for the next sweep, and is logged.
  4. Teardown is idempotent. Kills require `Number.isSafeInteger(pid) && pid > 1`.
- **`sweep()`:**
  - Read `pids.json`; missing or corrupt counts as empty.
  - For each entry with a valid pid and a `startedAt`: `cur = await psFn(pid)`.
    - If `cur?.startedAt === entry.startedAt`, the group is ours: run the same TERM → probe → KILL sequence.
    - If `cur` exists with a different `startedAt`, the PID was reused: skip it.
    - If `cur` is null (the leader is gone), `pgroupFn(pid)` lists the members of pgid `pid` (default `ps -A -o pid=,pgid=`). If there are any, kill the group, since POSIX doesn't reuse a pgid while members exist.
  - Remove only the entries it processed, never the whole file.
- **No `runMigrate`.** Process consumers migrate on boot.
- **`package.json` `exports`:** add `"./adapters/provisioner-process"`. Test it through a self-reference.

**Tests** use a fake `spawnFn` returning EventEmitter children, recording `killFn`/`psFn`/`pgroupFn`, a scripted `fetchFn` and a fake clock. They cover:
- the envs being exactly as specified;
- `detached` spawning;
- a spawn error (no pid) rejecting without a pidfile entry, and not crashing;
- the pidfile write serialization and `0600`;
- abort before spawning;
- the health check: success, an early exit with the tail, the deadline with a hung fetch (every fetch signal ends up aborted), and the `healthy` predicate;
- the database: ready, an early exit, `handle`;
- teardown: the leader exits on TERM while the group lives, so SIGKILL is still sent after the grace period; the entry is kept until ESRCH; ESRCH/EPERM tolerance; idempotency;
- sweep: `startedAt` match, reused-PID skip, a leaderless group killed via `pgroupFn`;
- the exit hook;
- the ring buffer surviving teardown and resetting on the next launch;
- no port collisions.
